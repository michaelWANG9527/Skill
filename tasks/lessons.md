# Lessons

## 2026-10-29 · Q3 财报情报邮件（对照 Gemini 版本后的纠正）

**纠正来源**：用户认为 Gemini 做的版本明显更好。

**我犯的错 → 规则**

1. **颜色违背本地读者习惯**：给中国管理层的财务材料用了“蓝涨橙跌”。
   → 中文 / A 股读者默认**红涨绿跌**；面向海外读者时再提供“绿涨红跌”切换。先问清读者，不要套用通用无障碍配色。
2. **信息密度不够**：为了“简洁”，砍掉了原币金额、净利润、研发费率、应付 / OCF、Q4 指引等字段。
   → 面向管理层的财报汇总，**数据完整性优先于留白**。源文件里的表格字段默认全部保留，再用分组、半表、注释控制阅读负担。
3. **只交付静态成品，没有交付“工具”**：用户要的是能反复改、能一键发出去的东西。
   → 邮件类交付，优先提供：一键复制带样式正文、导出 HTML、正文可直接编辑、模块筛选、底色切换。
4. **没问清邮件客户端**：我按 Outlook 做的 640px，用户实际用的是阿里企业邮箱。
   → 开工前确认收件客户端和宽度（例如阿里邮箱 PC 宽屏约 780px）。
5. **缺少视觉记忆点**：通篇只有排版，没有头图。
   → 刊头可以用一张轻量（约 30KB）的主题头图提升质感，同时注意部分客户端会拦截内嵌图片，需要有降级方案。
6. **溯源链接没有放进正文**：md 附录里已有巨潮资讯的官方链接，我却没用上。
   → 源材料里的出处链接要直接放进交付物的附录。

## 2026-10-29 · 删除“n=5 / n=15 合计与中位数”统计卡

**纠正来源**：用户看不懂友商组、客户组两张统计卡里的“Q3 合计营收”等数字，要求删除。
**规则**：把业务差异很大的公司营收直接加总，对管理层没有决策意义。只放读者一眼能看懂用途的数字；任何汇总指标都要先回答“它让读者做什么判断”，答不上来就不放。

## 2026-10-29 · 发出前必须逐份对照原文核对

**纠正来源**：用户在发送前追问“是否细致阅读过网盘里的文件”。实际情况是：此前只读了用户上传的 JSON、md 和 3 份 PDF，没有读网盘原文。
**规则**：
1. 对外发送的数据材料，交付前必须逐份对照一手原文核对；没核对过就明确说“未核对”，不能默认二手汇总是对的。
2. 引号里只放逐字原话；概括、拼接或推断的内容不加引号。
3. 归因要对准口径：不要把解释 A 指标的原文挪去解释 B 指标（例如用解释存货的话去解释毛利），也不要把前三季度口径写成单季、把展望写成已发生。
4. 推算值一律标 †，并在附录说明哪些不是推算值。

## 2026-10-29 · 用户要的是“对我司有用”的情报，不是财报摘要

**纠正来源**：用户认为 V5 维度不够高，要求把“启发”改为“可能的机会点”，并站在 CEO / Wi-Fi 芯片专家的角度升级。
**规则**：
1. 开工前先问清“我司是谁、卖什么”（本项目：Combo 连接芯片，Wi-Fi + BT 配套电视 / 机顶盒 / OTT / 平板），所有分析都围绕这个业务的需求、成本、库存、竞争、技术五个维度展开。
2. 机会点必须写清：依据（事实）、目标客户、时间窗、建议动作、风险 / 反证；事实与研判分开标注。
3. 季度趋势等需要半年报 / 一季报的数据，用三季报恒等式推算并标 †，再用公开报道交叉验证。
4. 外部行业数据只用有明确机构、日期、链接的数字，并标“机构原始发布”或“媒体转述”。
